# 0021 — На iOS нет kill switch («Без VPN — без сети»)

## Context

В сборках iOS 0.29.0 (3–5) был тумблер «Без VPN — без сети»:
`includeAllNetworks = true` + On-Demand. 2026-10-27 владелец обновлял
приложение из TestFlight (4 → 5) при поднятом туннеле — и iPhone остался без
интернета: обновление не докачивалось, приложение не открывалось, не помогали
ни авиарежим, ни переключение Wi-Fi, ни другой VPN. Помогла только перезагрузка.

По логам устройства: iOS убила расширение (SIGTERM от launchd, `stopTunnel` не
вызывался), приложение стало заглушкой «обновляется», а политика
`includeAllNetworks` продолжала гнать весь трафик в мёртвый utun. Поднять
туннель некому — провайдера нет, пока не завершится обновление; обновление не
завершится, пока нет сети. Это известный баг iOS (FB16482585); инженер Apple на
форумах: на уровне кода сделать почти ничего нельзя. Mullvad по той же причине
не включает этот флаг на iOS.

## Decision

Kill switch на iOS убран (решение владельца). `includeAllNetworks` всегда
`false`, `excludeLocalNetworks = true` (ADR 0019). При запуске приложение
снимает флаг с уже сохранённых конфигураций (`clearIncludeAllNetworks`).
Автоподключение (On-Demand) остаётся: без `includeAllNetworks` оно не
fail-closed, при мёртвом провайдере трафик идёт напрямую и обновление докачается.

## Alternatives

- **Оставить выключенным по умолчанию с предупреждением «отключите VPN перед
  обновлением»** — отклонено: забыл раз — телефон без сети до перезагрузки.
- **Ловить `.appUpdate` в `stopTunnel`** — не работает: при обновлении
  провайдер убивают без `stopTunnel`.

## Consequences

- Пока туннель переподключается, трафик может уйти мимо VPN (как у большинства
  iOS-клиентов). Защита от утечки IPv6 и DNS остаётся в самом туннеле.
- На macOS kill switch остаётся (`PreferencesStore.killSwitch` общий).
- Пользователям сборок 3–5 до перехода на новую: перед обновлением отключать VPN.
