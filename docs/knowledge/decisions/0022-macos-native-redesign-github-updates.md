# 0022 — macOS: нативный каркас как на iOS, обновления через GitHub Releases

## Context

Аудит 2026-10-28 ([отчёт](../audits/2026-10-28-macos-audit.md)) показал, что
macOS-клиент выглядит сыро:

- экраны перерисованы с HTML-мокапа литералами (232 `.font(.custom)`,
  около 8 самописных кнопок, самописные сайдбар, таблицы и тумблеры);
- половина текстов — английский жаргон;
- фирменные шрифты без кириллицы;
- ни одного системного материала на macOS 26.

Механизма обновлений нет вообще: Sparkle описан в
[platforms/macos.md](../platforms/macos.md), но в код не подключён, а в
настройках висит заглушка «Sparkle updater не подключен».

## Decision

Решения владельца:

1. **Дизайн.** Переводим на нативный каркас по образцу iOS:
   - `NavigationSplitView` с системным сайдбаром;
   - тулбар с крупной кнопкой «Подключить»;
   - `Table`, `Form` и нативные `Toggle`/`Picker`;
   - glass только на контролах (macOS 26);
   - фирменные цвета остаются, кириллица набирается системным шрифтом.

   Перед кодом — HTML-макет на утверждение.
2. **Обновления.** Приложение сравнивает свою версию с последним релизом на
   GitHub и показывает «Доступна версия X — Скачать». DMG пользователь ставит
   сам. Sparkle не подключаем.

## Alternatives

- **Оставить «терминальный» стиль и навести порядок** — отклонено: дешевле, но
  на фоне macOS 26 выглядит чужеродно и расходится с iOS.
- **Sparkle с автоустановкой** — отклонено: нужен ключ подписи EdDSA и appcast
  в каждом релизе; для пет-проекта с небольшим числом Mac-пользователей это
  лишняя инфраструктура.

## Consequences

- Заглушки Sparkle убираются из UI; раздел Sparkle в `platforms/macos.md`
  переписывается под проверку GitHub.
- Редизайн идёт поэкранно и вместе с переводом всех строк на каталог
  локализации.
