# 0023 — Сертификаты Минцифры только для .ru/.рф/.su (кнопка в iOS/Android)

## Context

Часть российских сайтов — в основном банки (Сбер, ВТБ) — отдают сертификаты
от `Russian Trusted Sub CA`, выпущенного `Russian Trusted Root CA` (Минцифры).
Браузеры этому корню не доверяют → «Подключение не защищено». Официальный
рецепт — поставить корень Минцифры в систему. Но корень **не ограничен по
именам** (нет Name Constraints): устройство начнёт верить любому серту, который
он выпустит, включая `google.com`. Владелец не хочет давать такую возможность.

Госуслуги и налоговая на 2026-10-28 работают на GlobalSign / Let's Encrypt —
им ничего не нужно. Банковским приложениям тоже: серт у них внутри.

## Decision

1. Свой корень `RU-only trust (.ru .rf .su) - local` с Name Constraints
   (permitted DNS `ru`, `xn--p1ai`, `su`; excluded все IP). Им переподписан
   (cross-sign) `Russian Trusted Sub CA` — тот же subject и ключ, издатель наш,
   те же ограничения. Корень Минцифры на устройство **не ставится**.
2. Закрытый ключ нашего корня существовал только в памяти генератора и
   уничтожен — выпустить под этот корень что-то ещё невозможно никому.
3. В настройках iOS и Android — строка «Сертификаты Минцифры» → окно с
   объяснением (что это, плюсы, риски, как удалить) → установка. Последний
   шаг пользователь подтверждает в системных настройках (iOS/Android иначе не
   дают). iOS: профиль `.mobileconfig` отдаётся Safari с loopback-сервера
   приложения. Android ≥ 11: файлы в Загрузки + переход в настройки
   безопасности; Android 8–10: `KeyChain.createInstallIntent`.

Файлы и генератор: `tools/ru-only-certs/`. Проверено: OpenSSL и `security
verify-cert` (macOS) принимают Сбер/ВТБ, а такой же комплект «только .su»
отвергает Сбер (`permitted subtree violation`).

## Проверка на устройствах (2026-10-28) — обе платформы не держат замысел

**Android — убрано (решение владельца, коммит `c2b3b0e2`).** Любой CA,
поставленный пользователем, становится якорем доверия. Chrome 145 **не
проверяет Name Constraints в якоре**: контрольный комплект «только .su»
(эмулятор, Android 17) пускает на `online.sberbank.ru`, в просмотрщике цепочка
leaf ← наш cross как якорь. То есть на Android фича доверяла бы Sub CA
Минцифры для **всех** доменов. Подложить cross как промежуточный (не якорь)
браузеру на Android некуда — ограничение там недостижимо.

**iOS — профиль ставится, но Safari сайты не открывает.** Проверка TLS в
Safari идёт в сетевом процессе WebKit (`NetworkingExtension.appex`, iOS 26),
у которого нет `keychain-access-groups`: cross из payload `pkcs1` лежит в
связке `com.apple.certificates`, и trustd отказывает WebKit (`-34018`). WebKit
видит только хранилище якорей (туда профиль кладёт лишь настоящие
self-signed корни), цепочку от сервера и AIA. Сам UI-процесс MobileSafari
цепочку leaf ← cross ← наш корень строит — поэтому статически всё «сходилось».
Apple ограничения в якоре соблюдает (проверено `security verify-cert`:
комплект «только .su» отвергается) — небезопасности нет, есть
неработоспособность.

Единственный найденный рабочий путь — **AIA**: все банковские листы
Минцифры указывают `http://nuc-cdp.voskhod.ru/cdp/subca_ssl_rsa2024.crt`
(запасной — `nuc-cdp.digital.gov.ru`), trustd качает его по HTTP и кеширует
~24 ч. Если вместо оригинала отдать наш cross, Safari открывает банк, а
контрольный «только .su» — нет (симулятор, подмена кеша trustd). Требует
подмены DNS этих хостов в VPN + маленький HTTP-эндпоинт на сервере; работает
только с включённым VPN или в пределах кеша. Не реализовано — ждёт решения
владельца.

## Alternatives considered

- **Корень Минцифры целиком** — отклонено: доверие ко всему интернету.
- **На уровне VPN (без установки на устройство)** — невозможно: серт проверяет
  браузер по хранилищу устройства. Единственный «сетевой» вариант — MITM с
  нашим собственным CA на устройстве, что хуже исходной проблемы.
- **Белый список доменов вместо зон** — отклонено владельцем: требует
  обновлений на каждый новый сайт; зоны достаточно.
- **Отдельный браузер (Яндекс)** — остаётся советом, но не решает «в моём
  браузере».

## Consequences

- Плюсы: банки открываются в браузере; подмена зарубежных сайтов Минцифры
  исключена; работает с VPN и без.
- Минусы: внутри .ru/.рф/.su подмена теоретически возможна (yandex.ru,
  mail.ru). На Android — системная пометка «Сеть может отслеживаться».
- Если Минцифры выпустит новый Sub CA — сайты на нём не откроются, пока не
  перегенерируем комплект (`make_ru_only.py`, обновить `SUB_SHA256`) и не
  выпустим приложения. Новый корень = пользователи переустанавливают профиль.
  Текущий Sub CA действует до 2029-07-19.
- OpenSSL/curl не умеют альтернативные цепочки → в терминале не работает,
  только браузеры/система.
