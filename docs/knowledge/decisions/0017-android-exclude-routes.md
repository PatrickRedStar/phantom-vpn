# 0017 — Split-routing на Android описывается через excludeRoute, а не через комплемент

- **Статус:** принят
- **Дата:** 2026-08-02
- **Зона:** `apps/android/.../GhostStreamVpnService.kt`, `apps/android/.../RoutingRulesManager.kt`
- **Заменяет:** практическую часть [0016](0016-android-route-budget.md) (бюджет остаётся, способ описания меняется)

## Контекст

После 0016 «раздельный туннель» перестал ронять Настройки, но перестал и
работать. Замер на Galaxy S21 (Android 15, geoip ru — 22 710 строк, 12 813
IPv4-блоков после слияния):

```
маршрутов на tun0:                1427
ip route get 77.88.55.242    →    dev tun0     # Яндекс уехал в туннель
маршрут, который его накрыл  →    77.88.0.0/13
```

Причина в том, как мы описывали разбиение. Комплемент («весь мир минус
Россия») стоит 29 961 маршрут: каждая дырка между российскими блоками требует
до 30 выровненных CIDR. Чтобы уложиться в бюджет 1500, склейка проглатывала
дырки размером до /17 — то есть ровно те подсети, ради которых split включают.
При бюджете 1500 терялись все проверенные сервисы; даже при 5404 маршрутах
(порог /12) Яндекс всё ещё в туннеле, а 9,2 млн российских адресов — вместе с
ним.

## Решение

Описывать то же самое разбиение с другой стороны: `addRoute(0.0.0.0/0)` плюс
`excludeRoute()` на каждый российский блок. Записей нужно 12 813 вместо 29 961,
и ни одна подсеть не теряется по построению.

Доступно с API 33; для API < 33 остаётся прежняя ветка с комплементом.

### Бюджет

Замеры на S21 дали два разных потолка, и решает меньший:

| Что упирается | Замер | Байт на запись |
|---|---|---|
| `establish()` | 12 820 префиксов → parcel 1 077 464 Б, `TransactionTooLargeException` | ≈84 |
| Чтение `LinkProperties` чужим процессом | 9 406 префиксов → reply `IConnectivityManager` 1 317 500 Б, падает **system_server** и уносит Настройки | ≈140 |

`EXCLUDE_BUDGET = 6000` даёт reply 840 660 Б — проверено, Настройки открываются.

### Как ужимаем список до бюджета

Два шага, в этом порядке:

1. **Мягкая склейка** с жёстким потолком `EXCLUDE_MAX_GAP = 1024` адреса.
   Проглоченный разрыв — чужие адреса, уходящие мимо туннеля, поэтому потолок
   фиксирован: на geoip ru это ≈1,5 млн адресов (0,03 % IPv4). Растить порог
   дальше нельзя — это нарушало бы инвариант dd94139b.
2. **Отбрасывание самых мелких блоков** до бюджета. Отброшенный блок едет через
   туннель: медленнее, но безопасно. На geoip ru отбрасывается ≈4400 блоков,
   RU-покрытие остаётся ≈98,9 %.

Асимметрия намеренная: потеря российской подсети — деградация удобства,
утечка чужого адреса — деградация приватности.

## Проверено на устройстве

S21, Android 15, `EXCLUDE_BUDGET = 6000`, geoip ru:

```
Exclude list trimmed to 6000 prefixes (4416 smallest dropped to tunnel)
ip route get 77.88.55.242  (Яндекс)  → via 192.168.1.1 dev wlan0    # direct
ip route get 87.240.190.78 (VK)      → via 192.168.1.1 dev wlan0    # direct
ip route get 213.219.247.1 (Т-Банк)  → via 192.168.1.1 dev wlan0    # direct
ip route get 8.8.8.8                 → dev tun0                     # туннель
ping 77.88.55.242 → 33 мс     ping 8.8.8.8 → 71 мс (через NL)
Настройки → Подключения → Другие настройки: открывается, reply 840 660 Б
```

## Последствия

- Ветка комплемента и `ROUTE_BUDGET = 1500` остаются для API < 33 со всеми
  прежними ограничениями: там split-routing по-прежнему теряет узкие подсети.
- `establish()` обёрнут в try/catch: переполнение parcel больше не роняет
  приложение, а даёт ошибку «Не удалось создать TUN».
- `127.0.0.0/8` в exclude не передаётся — VpnService отвечает `Bad address`.
- Списки докачиваются при подключении, если их нет, и тихо обновляются в фоне,
  если старше 30 дней.

## Пересмотр бюджета — 2026-10-28 (v0.29.1)

6000 оказалось мало: Samsung Watch Manager (`watchuniteplugin:persistent`)
читает `LinkProperties` из нескольких потоков сразу, общий binder-буфер
процесса (~1 МБ) не вмещает ответы, плагин падал с `DeadSystemException`
каждые 10–20 с, пока поднят VPN, — бесконечный рестарт, нагрев, батарея.
Замер на Z Fold (SM-F971B): 3000 — падает, 2000 — живы и плагин, и «Другие
настройки». `EXCLUDE_BUDGET = 1500` (≈210 КБ) — двукратный запас.

Цена: напрямую остаются блоки от /20, ≈79 % адресов geoip ru. Яндекс
(`77.88.0.0/18`) и VK (`87.240.128.0/18`) по-прежнему напрямую; Т-Банк
(`213.219.247.0`) и OK (`217.20.147.0`) теперь через туннель. Поднимать бюджет —
только с замером: VPN «РФ напрямую» + рестарт плагина часов + «Подключения →
Другие настройки».
